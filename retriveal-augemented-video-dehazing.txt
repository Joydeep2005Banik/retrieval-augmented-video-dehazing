in the prospects of video dehazing, a proposal of retrieval augmented video dehazing is a methos proposed. the flow diagram is as follows:
ground truth video -> frame extraction ->  feature extraction -> embedding features -> stord in vectorDB
input hazy video -> encoder -> feature extraction -> hazy vectors -> store in vectorDB -> vector dehazing -> dehazed vectors -> stored in vectorB -> decoder -> dehazed video as output
the entire idea revolves around the following steps:
step1: dataset; let the dataset be D={(Hi,Gi)} for i=1 to N
step 2: feature extraction; every frame is converted into an embedding. instead of storing the frames, the network compacts in a numeric where z=[z1,z2,....]. let embedding be E=f(s) where Zh=E(ht) denotes for hazy and Zg=E(gt) denotes for ground truth therefore Z=R^Es where Es=embedding size
step 3: vectorDB; vector can be stored in the form V={Zh,Zg}
step 4: vectorDB query; let Hk represent a frame of an input hazy video. thus embedding Zk=E(Hk). using either cosine similarity or euclid distance we retrieve most similiar clean or hazy features
step 5: feature aggregration; after step 4 lets say we get embeddings r1, r2, r3 etc. since we need a single embedding we either perform simple average or attention based aggregrate
step 6: dehazing; we concatenate hazy embeddings Zq and context embeddings R in X=[Zq, R]. X is put in the network that helps it to know hazy and retreived embeddings and provides output as g^(x)
step 7: loss; here we either perform pixel loss (L1=(1/N)*sum(gi-g^i) for i =1 to N), perceptual loss (L2=||phi(g^) - phi(g)||where phi() represents feature extractor, phi(g) represents clean image feature and phi(g^) represents predicted image feature) or contrastive retrieval loss ( L3=- log [{e^(cos(Zh,Zg)/tow)}/{sum(e^(cos(Zh,Zg)/tow)}] where tow represents temperature value that controls sharp feature similarity). thus the total loss is L=(L1*W1) + (L2*W2) + (L3*W3) where W1,W2,W3 are experimental weights
step 8: reconstruction; after step 7 we get predicted vectors that can be represented as h^={h1^, h2^,.....hT^}. after restorating we get G^={g1^,g2^,.....gT^}. this is encoded back to a video using encoding algorithm.
